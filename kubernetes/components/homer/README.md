# Homer (homer-operator Dashboard)

The Homer instance generated by [homer-operator](../homer-operator/README.md). Exposed at
`https://homer.<LOCAL_DOMAIN>`.

Nothing here lists services: the operator watches HTTPRoutes (Gateway API) and rebuilds the Homer config
on every reconcile, so **a new HTTPRoute appears on the dashboard automatically**, grouped by namespace,
with `https://<hostname>` as the link.

## Tuning what is shown

Per-HTTPRoute annotations (optional — an unannotated route is still listed):

| Annotation | Example |
|---|---|
| `item.homer.rajsingh.info/name` | `"Home Assistant"` |
| `item.homer.rajsingh.info/subtitle` | `"Home automation"` |
| `item.homer.rajsingh.info/icon` | `"fas fa-home"` (FontAwesome class) |
| `item.homer.rajsingh.info/hide` | `"true"` — keep the route off the dashboard |
| `service.homer.rajsingh.info/name` | `"Infrastructure"` — group name |
| `service.homer.rajsingh.info/icon` | `"fas fa-server"` |

Any other Homer parameter works too (`item.homer.rajsingh.info/<param>`).

Routes from the private repo (e.g. preview environments) are discovered as well; hide one there with
`item.homer.rajsingh.info/hide: "true"`.

Resources: single replica, `requests: 10m/32Mi`, no persistence.

Verify:

```bash
kubectl get dashboard -n homer
kubectl get dashboard homer -n homer -o jsonpath='{.status.discoveredHTTPRoutes}'; echo  # discovered routes
kubectl get pods -n homer
kubectl get configmap -n homer                 # generated homer config
```
